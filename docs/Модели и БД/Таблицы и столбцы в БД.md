# Таблицы

## Названия

Все названия таблиц должны соответствовать следующим правилам:

1. snake_case
1. с маленькой буквы
1. Множественное число

 > 
 > \[!tip\] Причины
 > Выбор lower_snake_case связан с регистронезависимостью SQL в Postgres
 > Множественное число выбрано, потому что оно семантически легче читается в SQL
 > 
 > ````sql
 > SELECT *
 > FROM users u
 > INNER JOIN user_profiles up on u.id=up.user_id
 > ````
 > 
 > Читается проще чем
 > 
 > ````sql
 > SELECT *
 > FROM "User" u
 > INNER JOIN "User_profile" up on u.id=up.user_id
 > ````

# Столбцы

## Названия

Все названия столбцов должны соответствовать следующим правилам:

1. snake_case
1. с маленькой буквы
1. единственное число
1. FK столбцы должны заканчиваться на `_id`

## Типы данных

1. Для дат используется `timestamp with time zone`
1. Для строковых типов используется только `TEXT`
1. Для целых чисел используется `SMALLINT`/`INTEGER`/`BIGINT`, для денег и прочих точных дробных значений — `NUMERIC(p,s)`
   * Запрет касается **хранения**: в контракте то же значение отдаётся обычным числом, в том числе дробным, и хранить его в минимальных единицах не требуется (см. [Принципы построения контрактов > Типы и форматы](../%D0%9F%D1%80%D0%B8%D0%BD%D1%86%D0%B8%D0%BF%D1%8B%20%D0%BF%D0%BE%D1%81%D1%82%D1%80%D0%BE%D0%B5%D0%BD%D0%B8%D1%8F%20%D0%BA%D0%BE%D0%BD%D1%82%D1%80%D0%B0%D0%BA%D1%82%D0%BE%D0%B2.md#tipy-i-formaty))
1. Для булевых значений используется `BOOLEAN`
1. ❌ Запрещённые  типы данных: все текстовые, кроме `TEXT`, `timetz`, `money`, `json` (не `jsonb`), `REAL`/`FLOAT`/`DOUBLE PRECISION`, массивы
1. ⚠ Нежелательные типы: `jsonb`
