# Назначение

Маппер — единственное место, где происходит преобразование данных между слоями. Допускается пропускать этап маппера, если структуры идентичны друг другу

Мапперы делятся на два типа: DTOMapper и EntityMapper.

|Преобразование|Кто вызывает|Тип маппера|
|--------------|------------|-----------|
|Request DTO → Internal DTO|[Контроллер](%D0%9A%D0%BE%D0%BD%D1%82%D1%80%D0%BE%D0%BB%D0%BB%D0%B5%D1%80%D1%8B.md)|DTOMapper|
|Entity → Модель|[Репозиторий](%D0%A0%D0%B5%D0%BF%D0%BE%D0%B7%D0%B8%D1%82%D0%BE%D1%80%D0%B8%D0%B8.md)|EntityMapper|
|[Модель](%D0%9C%D0%BE%D0%B4%D0%B5%D0%BB%D0%B8%20%D0%B8%20%D0%91%D0%94/Prisma%20%D0%BC%D0%BE%D0%B4%D0%B5%D0%BB%D0%B8.md) → Response DTO|[Сервис](%D0%A1%D0%B5%D1%80%D0%B2%D0%B8%D1%81%D1%8B.md)|DTOMapper|

# Реализация

Маппер — класс со static-методами, без DI. DTO создаются через конструкторы (см. [Валидация, сериализация и DTO > Конструкторы DTO](%D0%92%D0%B0%D0%BB%D0%B8%D0%B4%D0%B0%D1%86%D0%B8%D1%8F,%20%D1%81%D0%B5%D1%80%D0%B8%D0%B0%D0%BB%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F%20%D0%B8%20DTO.md#konstruktory-dto)):

````typescript
export class PostsMapper {
	// Request DTO → Internal DTO (вызывается контроллером)
	static toCreateDto(request: CreatePostRequestDto): CreatePostDto {
		return new CreatePostDto(request);
	}

	// Модель → Response DTO (вызывается сервисом)
	static toDto(model: Post): PostDto {
		return new PostDto(model);
	}

	static toListItemDto(model: Post): PostListItemDto {
		return new PostListItemDto(model);
	}
}
````

Для массивов методы переиспользуются: `models.map(PostsMapper.toDto)`.

Под каждое представление API — свой метод (`toDto()`, `toListItemDto()`): какой класс собирать, решает маппер, а не вызывающий код (см. [Валидация, сериализация и DTO > Производныe DTO](%D0%92%D0%B0%D0%BB%D0%B8%D0%B4%D0%B0%D1%86%D0%B8%D1%8F,%20%D1%81%D0%B5%D1%80%D0%B8%D0%B0%D0%BB%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F%20%D0%B8%20DTO.md#proizvodnye-dto)).

 > 
 > \[!info\] Compile-time проверка
 > Конструкторы DTO с явным присваиванием полей дают полную проверку компилятором: переименованное поле модели, пропущенное поле при создании или забытое присваивание в конструкторе — ошибка компиляции. Unit-тесты на заполненность полей не нужны.

# Правила

1. **Маппер возвращает инстансы классов.** Конструкторы DTO это гарантируют. Plain object, вернувшийся из маппера, — баг: `ClassSerializerInterceptor` на нём молча не сработает.
1. **Никакой бизнес-логики.** Маппер — чистое преобразование структуры. Вычисляемые значения считает сервис и передаёт параметром:
   ````typescript
   static toDto(model: Post, commentsCount: number): PostDto {
   	return new PostDto({ ...model, commentsCount });
   }
   ````

1. **Вложенные структуры маппятся мапперами своих модулей:**
   ````typescript
   static toDto(model: Post): PostDto {
   	return new PostDto({
   		...model,
   		author: UsersMapper.toDto(model.author),
   	});
   }
   ````
