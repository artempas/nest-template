# Конфигурация

Все настройки приложения приходят из переменных окружения. Прямое чтение
`process.env` в коде приложения запрещено — единственная точка доступа —
[`AppConfigService`](../src/lib/config/config.service.ts) из `@lib/config`.

Исключение — код вне Nest-контейнера (`prisma/seed.ts`, `prisma.config.ts`,
`test/*`): там DI нет, поэтому окружение читается напрямую.

## Из чего состоит `@lib/config`

| Файл | Роль |
|------|------|
| [`env.validation.ts`](../src/lib/config/env.validation.ts) | Класс `EnvironmentVariables` — полный контракт окружения с `class-validator`-декораторами. `validateEnv` — `validate`-хук для `ConfigModule`, падает на старте с человекочитаемым списком проблем |
| [`config.service.ts`](../src/lib/config/config.service.ts) | `AppConfigService` — типобезопасные геттеры поверх `ConfigService`. Сгруппированные конфиги (хост + порт + креды одного сервиса) отдаются готовым объектом |
| [`config.module.ts`](../src/lib/config/config.module.ts) | `@Global()`-модуль: `ConfigModule.forRoot` (загрузка `.env`, кэш, валидация) + провайд `AppConfigService` |

`ConfigModule` помечен `@Global()` (как `PrismaModule` / `LoggerModule`) —
повторно импортировать в модулях не нужно. `LoggerModule` и `PrismaModule`
получают конфиг через DI (`forRootAsync` / конструктор).

## Переменные окружения

| Переменная | Тип | По умолчанию | Назначение |
|------------|-----|--------------|------------|
| `DATABASE_URL` | string | — (обязательна) | Подключение к PostgreSQL. `?schema=` задаёт схему (см. `PrismaService.schema`) |
| `DATABASE_CONNECT_TIMEOUT_MS` | int ≥ 0 | `5000` | Таймаут установки соединения с БД, мс. `0` — без таймаута |
| `PORT` | 1–65535 | `3000` | Порт HTTP-сервера |
| `NODE_ENV` | `development` \| `production` \| `test` | `development` | Влияет на формат и уровень лога (см. [Логирование](%D0%9B%D0%BE%D0%B3%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5.md)) |
| `LOG_LEVEL` | `trace`…`silent` | `info` в prod, `warn` в тестах, иначе `debug` | Уровень лога |
| `BASE_PATH` | string | `""` | Базовый путь приложения за reverse proxy (напр. `/app/my-app`, без слеша на конце) — прокидывается в Swagger (`DocumentBuilder.addServer`), чтобы Swagger UI слал запросы по правильному префиксу |

Актуальный список с примерами — в [`example.env`](../example.env).

## Как добавить новую настройку

1. Поле в `EnvironmentVariables` с `class-validator`-декораторами. Необязательное
   — `@IsOptional()` + значение по умолчанию прямо на поле.
2. Геттер в `AppConfigService`. Связанные значения (хост + порт + креды одного
   сервиса) — одним типизированным объектом, а не набором геттеров.
3. Строка в `example.env` и в таблице выше.
4. Если настройка обязательна, а тестам, которым не поднять реальный сервис, она
   не нужна, — заглушка в [`test/setup-env.ts`](../test/setup-env.ts)
   (валидация окружения гоняется и в `createTestApp`).

 > 
 > \[!warning\] Boolean из окружения
 > `validateEnv` включает `enableImplicitConversion`, а неявная конверсия
 > отрабатывает раньше `@Transform` и делает из строки `"false"` — `true`. Для
 > boolean-переменной читай сырое значение из `obj`:
 > `@Transform(({ obj }) => obj.MY_FLAG === 'true') @IsBoolean()`.
