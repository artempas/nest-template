Контроллер — тонкий слой: разбирает запрос в DTO, вызывает [сервис](%D0%A1%D0%B5%D1%80%D0%B2%D0%B8%D1%81%D1%8B.md) и разворачивает результат (см. [Обработка ошибок > Контроллер](%D0%9E%D0%B1%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%BA%D0%B0%20%D0%BE%D1%88%D0%B8%D0%B1%D0%BE%D0%BA.md#kontroller)). Валидация запроса и сериализация ответа не описываются вручную в каждом контроллере — в проекте включены глобально `ValidationPipe` и `ClassSerializerInterceptor` (конфигурация и почему — в [Валидация, сериализация и DTO](%D0%92%D0%B0%D0%BB%D0%B8%D0%B4%D0%B0%D1%86%D0%B8%D1%8F,%20%D1%81%D0%B5%D1%80%D0%B8%D0%B0%D0%BB%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F%20%D0%B8%20DTO.md)).

# Пути через EndpointBuilder

Пути контроллера собираются через [EndpointBuilder](EndpointBuilder.md), а не пишутся строками вручную.

## Билдеры — публичная статика контроллера

Каждый контроллер хранит два билдера в публичном статическом поле `builders`:

|Билдер|Указывает на|
|------|------------|
|`root`|корень ресурса (`posts`)|
|`id`|конкретный экземпляр (`posts/:postId`)|

Билдер собирается из базового пути ресурса — константы в `*.tokens.ts` (см. [Токены](%D0%A2%D0%BE%D0%BA%D0%B5%D0%BD%D1%8B.md)):

````typescript
// posts/posts.tokens.ts
export const POSTS_BASE_PATH = 'posts';
````

````typescript
// posts/posts.controller.ts
import { POSTS_BASE_PATH } from './posts.tokens';

@Controller()
export class PostsController {
  static readonly builders = {
    root: EndpointBuilder.base(POSTS_BASE_PATH),
    id: EndpointBuilder.base(POSTS_BASE_PATH).param('postId'),
  };
}
````

 > 
 > \[!important\] В `@Controller()` префикс не передаётся
 > Декоратор класса всегда вызывается **без аргумента** — весь путь целиком лежит в `paths` и указывается на хендлере. Иначе путь склеивался бы из префикса и полного пути и задваивался: особенно заметно на вложенных ресурсах, где `paths` уже содержит родительские сегменты.

Поле публично не для красоты — именно на него ссылаются контроллеры вложенных ресурсов (см. ниже). Это тот же принцип межмодульного переиспользования статики, что уже применяется к гардам (см. [Гарды > Гарды переиспользуются между модулями](%D0%93%D0%B0%D1%80%D0%B4%D1%8B.md#gardy-pereispol-zuiutsia-mezhdu-moduliami)).

## Пути — один плоский объект paths

Все пути контроллера — включая кастомные действия, не только `root`/`id` — собираются в единый публичный объект `paths`. В нём лежат **`Endpoint`, а не строки**: строка нужна декоратору, а тестам нужен объект целиком.

````typescript
static readonly paths = {
  findMany: PostsController.builders.root.build(),
  createOne: PostsController.builders.root.build(),
  findOne: PostsController.builders.id.build(),
  archive: EndpointBuilder.extend(PostsController.builders.id).segment('archive').build(),
};
````

В декораторе хендлера у `Endpoint` берётся путь-шаблон: `@Get(PostsController.paths.findOne.getPath())`.

Публичность нужна тестам: `Endpoint` умеет `getWithParams({ postId: 5 })` — подставлять значения в путь без ручной конкатенации строк (см. [EndpointBuilder](EndpointBuilder.md), [Тестирование > Тест работает только через API](%D0%A2%D0%B5%D1%81%D1%82%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5.md#test-rabotaet-tol-ko-cherez-api)). Поэтому `paths` и хранит `Endpoint`: из строки, полученной `getPath()`, подставить параметры уже нельзя.

**Ключ в `paths` — имя метода-хендлера, который использует этот путь** (`findOne` → `@Get(paths.findOne.getPath()) findOne(...)`). Отдельной схемы имён заводить не нужно: путь и обработчик называются одинаково, поэтому оба находятся по одному имени.

## Вложенные ресурсы — extend()

Если ресурс вложен в другой (`posts/:postId/comments`), его билдеры продолжают билдеры родителя через `EndpointBuilder.extend()`, а не собираются с нуля:

````typescript
// comments/comments.controller.ts
import { PostsController } from '@modules/posts';

@Controller()
export class CommentsController {
  static readonly builders = {
    root: EndpointBuilder.extend(PostsController.builders.id).segment('comments'),
    id: EndpointBuilder.extend(PostsController.builders.id).segment('comments').param('commentId'),
  };

  static readonly paths = {
    findMany: CommentsController.builders.root.build(),
    createOne: CommentsController.builders.root.build(),
    findOne: CommentsController.builders.id.build(),
  };
}
````

Чужой контроллер импортируется через barrel-файл модуля по алиасу (`@modules/posts`), а не относительным путём в обход `index.ts` — см. [Codestyle и конвеции > Import](Codestyle%20%D0%B8%20%D0%BA%D0%BE%D0%BD%D0%B2%D0%B5%D1%86%D0%B8%D0%B8.md#import).

# Именование path-параметров

Path-параметры никогда не называются generic-именем вида `id` — только по правилу `названиеМоделиId` (`postId`, `commentId`).

Именно на этом правиле держится переиспользование гардов между модулями (см. [Гарды > Гарды переиспользуются между модулями](%D0%93%D0%B0%D1%80%D0%B4%D1%8B.md#gardy-pereispol-zuiutsia-mezhdu-moduliami)) — гард ищет `request.params.postId`, и ему всё равно, в каком контроллере физически объявлен маршрут.

# Path-параметры валидируются через DTO

Как и всё остальное, что приходит от клиента (см. [Валидация, сериализация и DTO](%D0%92%D0%B0%D0%BB%D0%B8%D0%B4%D0%B0%D1%86%D0%B8%D1%8F,%20%D1%81%D0%B5%D1%80%D0%B8%D0%B0%D0%BB%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F%20%D0%B8%20DTO.md)), path-параметры не читаются поштучно через `ParseIntPipe`/`ParseUUIDPipe` — они собираются в DTO и валидируются глобальным `ValidationPipe` целиком:

````typescript
// posts/contracts/request/post-params.contract.ts
export class PostParamsDto {
  @Transform(({ value }) => Number(value))
  @IsNaturalNumber()
  postId: number;
}
````

````typescript
// posts/posts.controller.ts
@Get(PostsController.paths.findOne.getPath())
async findOne(@Param() params: PostParamsDto): Promise<PostDto> {
  return unwrapOrThrow(await this.postsService.findOneOrFail(params.postId));
}
````

## Вложенный DTO расширяет родительский

DTO вложенного пути не переобъявляет родительские параметры, а расширяет DTO родительского ресурса обычным `extends` — не `PickType`/`OmitType`: те выбирают подмножество полей базового DTO, а тут наоборот, новое поле добавляется поверх родительских (см. [Валидация, сериализация и DTO > Производныe DTO](%D0%92%D0%B0%D0%BB%D0%B8%D0%B4%D0%B0%D1%86%D0%B8%D1%8F,%20%D1%81%D0%B5%D1%80%D0%B8%D0%B0%D0%BB%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F%20%D0%B8%20DTO.md#proizvodnye-dto)):

````typescript
// comments/contracts/request/comment-params.contract.ts
import { PostParamsDto } from '@modules/posts';

export class CommentParamsDto extends PostParamsDto {
  @Transform(({ value }) => Number(value))
  @IsNaturalNumber()
  commentId: number;
}
````

Как и любой Request DTO, `*ParamsDto` объявляется **без конструктора** — инстанс собирает `ValidationPipe` (см. [Валидация, сериализация и DTO > Конструкторы DTO](%D0%92%D0%B0%D0%BB%D0%B8%D0%B4%D0%B0%D1%86%D0%B8%D1%8F,%20%D1%81%D0%B5%D1%80%D0%B8%D0%B0%D0%BB%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F%20%D0%B8%20DTO.md#konstruktory-dto)).

 > 
 > \[!warning\] Гарды по-прежнему читают params напрямую
 > Гарды выполняются **до** пайпов в жизненном цикле Nest — то есть до того, как `ValidationPipe` соберёт и провалидирует `*ParamsDto`. Переход на Path DTO ничего не меняет для гардов: они, как и раньше, читают `request.params.postId` напрямую и приводят тип сами (см. [Гарды > Гард смотрит только на path-параметры](%D0%93%D0%B0%D1%80%D0%B4%D1%8B.md#gard-smotrit-tol-ko-na-path-parametry)).

# Данные пользователя — @AuthHeaders

Данные о текущем пользователе (actor) извлекаются из заголовков запроса декоратором `@AuthHeaders()`, а не читаются вручную:

````typescript
// common/decorators/auth-headers.decorator.ts
export const AuthHeaders = createParamDecorator(
  (_: unknown, ctx: ExecutionContext) => ctx.switchToHttp().getRequest().headers,
);
````

````typescript
// common/dtos/auth-headers.dto.ts
export class AuthHeadersDto {
  @Expose({ name: 'user_id' })
  @Transform(({ value }) => Number(value))
  @IsNaturalNumber()
  actorId: number;
}
````

````typescript
// posts/posts.controller.ts
@Post(PostsController.paths.createOne.getPath())
async createOne(
  @Body() dto: CreatePostRequestDto,
  @AuthHeaders() auth: AuthHeadersDto,
): Promise<PostDto> {
  return unwrapOrThrow(
    await this.postsService.createOne(PostsMapper.toCreateDto(dto), auth.actorId),
  );
}
````

`AuthHeadersDto` — Request DTO без конструктора, как и `*ParamsDto` выше: декоратор лишь передаёт сырые заголовки, а валидирует и трансформирует их тот же глобальный `ValidationPipe`, что и `@Body()`/`@Query()`/`@Param()` — специальный пайп под `@AuthHeaders()` не нужен.
