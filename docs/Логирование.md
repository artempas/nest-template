Логирование в проекте построено на [`nestjs-pino`](https://github.com/iamolegga/nestjs-pino) — тонкой обёртке над [`pino`](https://getpino.io) и `pino-http`. Логгер отдаёт **структурированный** лог: в production — строчный JSON в stdout (готов к сбору в Loki / ELK / CloudWatch), в остальных случаях — человекочитаемый цветной вывод через `pino-pretty`.

# Что логируется

## Автоматический лог каждого HTTP-запроса

`pino-http` пишет одну строку на завершённый ответ:

```json
{"level":30,"time":1712345678901,
 "req":{"id":"a1b2c3","method":"GET","url":"/users/42","headers":{...}},
 "res":{"statusCode":200},"responseTime":14,"msg":"request completed"}
```

- **`req.id`** — id запроса. Берётся из заголовка `X-Request-Id`, если он пришёл, иначе генерируется (`randomUUID`). Этот же id уезжает в ответ заголовком `X-Request-Id` и подставляется во все логи, написанные внутри запроса.
- **Уровень строки** зависит от статуса ответа: `5xx` или проброшенное исключение → `error`, `4xx` → `warn`, остальное → `info`.
- Тело запроса и ответа **не логируются**. Заголовки логируются — про секреты см. [Чувствительные данные](#Чувствительные-данные).
- Запросы к `/health*` и `/swagger*` в лог не попадают.

## Логи самого приложения

После `app.useLogger(app.get(Logger))` (вызывается в [`configureApp`](../src/lib/bootstrap/configure-app.ts)) через pino идёт весь встроенный вывод Nest (маршруты на старте, `ExceptionFilter`, `ClassSerializerInterceptor`) и всё, что написано через штатный `Logger`.

Внутри сервиса/репозитория логгер инжектится конструктором:

```typescript
import { PinoLogger } from 'nestjs-pino';

@Injectable()
export class PostsService {
  constructor(private readonly logger: PinoLogger) {
    this.logger.setContext(PostsService.name);
  }

  async publish(id: number): Promise<void> {
    this.logger.info({ postId: id }, 'публикую пост');
  }
}
```

`LoggerModule` помечен `@Global()` (как `PrismaModule`), поэтому повторно импортировать его в модулях не нужно. Первым аргументом `pino`-методов идёт объект с полями (`{ postId: id }`), вторым — текст сообщения. Строки, написанные во время обработки запроса, автоматически получают его `req.id`.

# Конфигурация

Единственный источник настроек — переменные окружения, разбираются в [`buildLoggerParams`](../src/lib/logger/logger.config.ts):

| Переменная  | Значения                                                    | По умолчанию |
|-------------|------------------------------------------------------------|--------------|
| `LOG_LEVEL` | `trace` `debug` `info` `warn` `error` `fatal` `silent`      | `info` в production, иначе `debug` |
| `NODE_ENV`  | `production` включает JSON-вывод; иначе `pino-pretty`       | —            |

Менять формат/редакцию/фильтры путей — в `logger.config.ts`, а не в `main.ts`: функция общая с тестовой обвязкой.

# Чувствительные данные

`redact` вырезает значения секретных заголовков из лога полностью (`remove: true`):

- `req.headers.authorization`
- `req.headers.cookie`
- `res.headers["set-cookie"]`

Появился новый заголовок/поле с секретом — добавь его путь в `REDACT_PATHS` в [`logger.config.ts`](../src/lib/logger/logger.config.ts).

LOG_LEVEL=debug pnpm test:e2e
