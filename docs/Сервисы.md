Сервис — место бизнес-логики модуля. Он оркеструет [репозитории](%D0%A0%D0%B5%D0%BF%D0%BE%D0%B7%D0%B8%D1%82%D0%BE%D1%80%D0%B8%D0%B8.md), [мапперы](%D0%9C%D0%B0%D0%BF%D0%BF%D0%B5%D1%80%D1%8B.md) и сервисы других модулей

Все методы репозитория возвращают `Result` (см. [Репозитории > Обработка ошибок](%D0%A0%D0%B5%D0%BF%D0%BE%D0%B7%D0%B8%D1%82%D0%BE%D1%80%D0%B8%D0%B8.md#obrabotka-oshibok)), поэтому их результат нельзя использовать как значение напрямую: сервис обязан разобрать `Result` — либо перевести инфраструктурную ошибку в доменную, либо пробросить её дальше (см. [Обработка ошибок > Best-effort перевод инфра → домен](%D0%9E%D0%B1%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%BA%D0%B0%20%D0%BE%D1%88%D0%B8%D0%B1%D0%BE%D0%BA.md#best-effort-perevod-infra-domen)).

Методы сервиса не кидают исключения, а **возвращают** `Result`: каждый метод помечен `@NeverThrow()` и типизирован `ServiceResult<T, E>`, где `E` — доменные ошибки метода (плюс всегда неявный `UnhandledError`). Механика — в \[\[Обработка ошибок#Сервис: `@NeverThrow` и `ServiceResult`\]\].

# Три уровня видимости метода

У сервиса не два уровня видимости («приватно/публично»), а фактически три — TypeScript-модификатор и межмодульный контракт решают разные вопросы:

|Уровень|Модификатор|Кто может вызвать|
|-------|-----------|-----------------|
|Приватный|`private`|только сам сервис (внутренняя декомпозиция логики)|
|Публичный в модуле|без модификатора|[контроллер](%D0%9A%D0%BE%D0%BD%D1%82%D1%80%D0%BE%D0%BB%D0%BB%D0%B5%D1%80%D1%8B.md) и другие сервисы **этого же модуля**|
|Публичный между модулями|входит в экспортируемый интерфейс|сервисы **других модулей**|

`private` — это методы, на которые остальной код сервиса опирается ради разбиения на шаги, но снаружи класса они не существуют. Публичные методы без модификатора — обычный рабочий интерфейс сервиса внутри своего модуля. Ни один из этих уровней сам по себе не решает, что можно дать другим модулям, — для этого нужен явный интерфейс.

# Экспортируемый интерфейс

Не любой публичный метод сервиса автоматически становится доступен другим модулям. Методы, которые сервис готов открыть наружу, перечисляются в отдельном интерфейсе — это осознанный, явно описанный контракт, а не побочный эффект того, что метод не помечен `private`.

````typescript
// posts/posts.service.ts
export interface IPostsService {
  findManyPublishedByAuthor(authorId: number): ServiceResult<PostDto[], never>;
}

@Injectable()
export class PostsService implements IPostsService {
  constructor(
    private readonly postsRepository: PostsRwRepository,
    private readonly assetsRepository: AssetsRoRepository,
  ) {}

  // входит в IPostsService — часть контракта для других модулей.
  // Доменных ошибок нет (E = never), но UnhandledError в Result есть всегда
  @NeverThrow()
  async findManyPublishedByAuthor(authorId: number): ServiceResult<PostDto[], never> {
    // репозиторий возвращает Result — его нельзя использовать как значение
    const result = await this.postsRepository.findManyPublishedByAuthor(authorId);
    if (result.isErr()) throw result.error; // инфра-сбой — best-effort, завернёт @NeverThrow
    return ok(result.value.map(PostsMapper.toDto));
  }

  // публичный, но не в интерфейсе — вызывается только контроллером posts
  @NeverThrow()
  async createOne(dto: CreatePostDto, actorId: number): ServiceResult<PostDto, PostTooLongError> {
    if (dto.content.length > POST_MAX_LENGTH) {
      return err(new PostTooLongError(dto.content.length, POST_MAX_LENGTH));
    }
    const result = await this.postsRepository.createOne(dto, actorId);
    if (result.isErr()) throw result.error;
    return ok(PostsMapper.toDto(result.value));
  }

  // приватный — деталь реализации, не существует снаружи класса;
  // Result/@NeverThrow не требуются — он не часть интерфейса сервиса
  private buildExcerpt(content: string): string {
    return content.slice(0, 200);
  }
}
````

`createOne` публичен на уровне TS (его вызывает `PostsController`), но не входит в `IPostsService` — другим модулям создание постов не нужно, а значит и в контракте ему не место. Контракт должен быть минимальным: чем он у́же, тем меньше у модуля-потребителя причин ломаться при рефакторинге `PostsService`.

# Импорт чужого сервиса — только через интерфейс

Если сервис модуля A использует сервис модуля B, он обязан типизировать зависимость интерфейсом (`IPostsService`), а не конкретным классом (`PostsService`). Механизм — DI-токен (см. [Токены](%D0%A2%D0%BE%D0%BA%D0%B5%D0%BD%D1%8B.md)):

````typescript
// posts/posts.tokens.ts
export const POSTS_SERVICE = Symbol('PostsService');
````

````typescript
// posts/posts.module.ts
@Module({
  providers: [
    PostsService,
    { provide: POSTS_SERVICE, useExisting: PostsService },
  ],
  exports: [POSTS_SERVICE],
})
export class PostsModule {}
````

````typescript
// comments/comments.service.ts
@Injectable()
export class CommentsService {
  constructor(
    @Inject(POSTS_SERVICE)
    private readonly postsService: IPostsService, // интерфейс, не PostsService
  ) {}
}
````
